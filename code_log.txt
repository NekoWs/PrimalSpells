一、项目模块总览
------------------------------------------------------------
- item/       WandItem(法杖)、SpellPouchItem(法术小包)、ModItems(注册)、
              SpellPouchInventory/Menu(容器)、ModMenus(MenuType)
- wand/       Wand、WandManager、WandSavedData（服务端法杖数据）
- magic/      法术系统：Magic、Projectile、Revise、TriggerSpell、MagicManager、
              effect/ 与 projectile/ 下大量法术
- entity/     实体：Cube/Sphere/Drone/TestDummy + AI Goal
- ui/         UI 框架（重点）：
    - UiScreen/UiBuilder/UiElement(UiWindow/UiButton/UiLabel/UiImage/UiSlot)
    - html/HtmlUiParser（HTML→UI 转换器）、HtmlUiLoader
    - FloatingWindow + FloatingWindowManager（法杖信息窗）
    - pouch/SpellPouchWindow + PouchWindowManager（小包悬浮窗）
    - slot/SlotDragController（槽位拖拽，数据权威化）
    - common/SpellSlotGrid、TrackedContainerWindow、ContainerWindowBase
- block/       WandEditingTableBlock（法杖编辑台）
- network/     SyncWandStatsPayload、EditWandPayload、EditPouchPayload、
              SelectWandSlotPayload、SyncShieldPayload
- client/      PrimalSpellsClient、ClientTooltipHandler、WandHudRenderer、
              SpellPouchScreen、PouchTooltip、ShieldHudRenderer
- mixin/       AbstractContainerScreenMixin、AbstractContainerScreenInvokerMixin

注：UI 文件位于 work.nekow.nekoui 包（NekoUi 常量提供 MODID/LOGGER），
资源命名空间仍为 primalspells。

二、关键修复历史（摘要）
------------------------------------------------------------
1. 26.2 迁移：按新渲染管线（EntityRenderState + SubmitNodeCollector.submitModel）
   补齐 entity 渲染类；BLOCKS.register 需 setId(ResourceKey) + noLootTable()。
2. 编辑台"网络协议错误"：MenuType 方案 → 纯客户端 Screen 绕开；
   小包容器 UI 恢复用菜单系统且正常（编辑台错误未深究）。
3. dev 资源加载：ModuleClassLoader 在 Windows dev 崩溃 → ResourceManager/文件系统；
   HTML 优先读源码目录（Path 向上两级找项目根），改 HTML 保存即热重建浮窗
   （HtmlUiLoader.isModified 按 mtime 检测，保留位置/追踪状态）。
4. 浮窗渲染层级：HUD 层在 Screen 之前 → ScreenEvent.Render.Post（Screen 后）；
   后改容器屏幕用 ContainerScreenEvent.Render.Foreground（低于拖拽物品/tooltip，
   pose 已 translate 需 pushMatrix + translate(-getLeftPos,-getTopPos) 重置），
   非容器屏幕仍用 Post（Post 处理器对容器屏幕直接 return 防重复）。
5. 浮窗闪烁：gameTime 去重在高帧率下每 tick 只画一次 → 删去重，改内容缓存。
6. 【原则】浮窗数据绝不缓存物品引用，每次 refresh 从容器/背包按 ID 重取
   （TrackedContainerWindow 基类统一实现：按 ID 定位手持/副手/背包 → 网格
   updateGrid → 丢失 onLost 隐藏窗口）。
7. 拖放系统重构"数据权威化"：槽位 stack 永远来自服务端同步，拖动只做渲染层
   隐藏（UiSlot.picked）+ 释放产生交换意图（lastSwap→SWAP），源槽数据不破坏，
   天然支持拖回/放空。跨窗拖动经 ContainerWindowBase 注册表 + acceptExternalSpell。
8. 小包定位全面改为唯一 ID（POUCH_ID 组件，独立 DataComponentType 实例——
   同一实例注册两次会 "duplicate value" 崩溃）：EditPouchPayload.pouchSlot→pouchId，
   服务端/客户端均遍历背包按 ID 查找，修复复制/消失/不同步/放错格。
9. 原版容器拖放交换：mixin @Invoker 公开 slotClicked；Ctrl+左键按下拾起、
   释放到容器槽两步 PICKUP 互换（先目标槽再原槽，物品留槽光标清空）、
   同槽释放不取消原版（=单击拾起）、CraftingScreen 内整体禁用。
10. HTML 转换器：width/height:auto、display:flex、hr/a/progress/checkbox/
   spell-grid 标签、#RRGGBBAA/rgb()/rgba()、font-size 缩放、hidden、
   完整 HTML 文档兼容、id/classList + <style> 类选择器（:hover 动态匹配）。
   【规则】窗口根 div 的 title 仅顶栏标题；嵌套 div 的 title 才是面板标题
   （uichecker 预览端与游戏转换器必须同步遵守）。
11. 触发火球无后续法术时重抽自身：castHand 的 discard() 移到 for 循环后，
   payload 抽取发生在牌堆重置之前。
12. 被动法术系统（onInventoryTick）+ 能量盾【已验证】：
   Magic.needInventory + onInventoryTick()；Wand.tick(caster) 驱动
   （WandItem.inventoryTick 仅 MAINHAND/OFFHAND；主手每 tick 触发两次需按
   gameTime 去重）；EnergyShield：耐久 100/回复 10/s/破盾暂停 200tick，
   弹开接近的非己方投射物（反射 velocity + 推出），HUD 盾条在准星下方
   （SyncShieldPayload 按状态变化去重发包）。
13. 测试木桩 + 伤害数字【已验证】：TestDummyEntity 继承 ArmorStand

   billboard=center 始终面向玩家、跳出动画经 transformation 每 tick 重写 +

三、26.2 易踩坑技术点（务必记住）
------------------------------------------------------------
- API 勘误（与 1.21.x 差异）：
  * ClickType → ContainerInput；Minecraft.getTimer() → getDeltaTracker()
  * net.minecraft.Util → net.minecraft.util.Util；Player 在
    net.minecraft.world.entity.player.Player
  * Screen.hasShiftDown() 移除 → Minecraft.getInstance().hasShiftDown()
  * AbstractContainerScreen：getLeftPos()/getTopPos()/getHoveredSlot()
    （NeoForge getter）；getGuiLeft/getGuiTop/getSlotUnderMouse deprecated
  * 传送：Entity.teleportTo(ServerLevel, x,y,z, Set<Relative>, yaw,pitch,
    resetCamera)；简单版 teleportTo(x,y,z) 只是 snapTo 不给客户端发包
  * SoundEvents 常量混杂：老 SoundEvent / 新 Holder.Reference（需 .value()）
  * EntityType 静态字段在 EntityTypes 类（EntityTypes.TEXT_DISPLAY）；
    Attributes 包为 net.minecraft.world.entity.ai.attributes.Attributes
- 物品每 tick 驱动：主手选中槽每 tick 触发两次 inventoryTick（Inventory.tick
  + EntityEquipment.tick），需按 level.getGameTime() 去重。
- Kotlin：lateinit 的 ::isInitialized 在子类/跨包作用域编译报错；
  JOML Vector3f 的 normalize/reflect/dot 均原地修改返回自身；
  0xFFFF4545 类字面量超出 Int 范围需 .toInt() 或显式类型。
- PowerShell 5.1：函数名不能撞内置别名（FC→Format-Custom，别名优先）；
  .ps1 中文注释必须 UTF-8 BOM 或纯 ASCII，否则多字节误读吞代码行。
- javap 验证类时 ~/.gradle/caches/neoformruntime/ 可能混有旧版本残留 jar，
  26.2 正确产物在 build/neoForm/neoFormJoined26.2-1/。
- 物品模型：assets/<ns>/items/<name>.json 引用 models/item/*.json，缺则贴图不生效。
- GUI atlas 只扫描 textures/gui/sprites/；容器背景用 textures/gui/container/*.png
  + graphics.blit(RenderPipelines.GUI_TEXTURED, id, x, y, 0f, 0f, iw, ih, 256, 256)。
- Slot.x/y 是相对菜单坐标，屏幕坐标 = getLeftPos()+slot.x。
- Screen.isInGameUi() 控制背景模糊/暗化与 HUD 显示。
- NeoForge.EVENT_BUS.register(对象) 的 @SubscribeEvent 不能 @JvmStatic。
- 客户端发包用 ClientPacketDistributor.sendToServer。
- 输入：mouseClicked(MouseButtonEvent,boolean)、keyPressed(KeyEvent)；
  ScreenEvent.MouseButtonPressed/Dragged/Released.Pre 可拦截并 event.isCanceled。
- 构建/改资源前先结束游戏进程（Windows 文件锁）；dev 改 src 资源需
  processResources 或重启（HTML 例外，直接读源码目录）。
- IDE 打开着的旧缓冲可能覆盖磁盘：改完务必确认磁盘内容 + 编译通过。
- 26.2 HUD 布局：leftHeight 初始 39；心形条底行 y = guiHeight - leftHeight；
  物品图标渲染 16x16 画在 (slot.x, slot.y)，不 +1 居中；悬停高亮 24x24
  画在 (slot.x-4, slot.y-4)。

四、UI/交互架构现状
------------------------------------------------------------
- 法杖信息浮窗：打开游戏内 UI 显示最小化窄顶栏（首次定位屏幕右侧，之后位置持久）；
  悬停背包法杖展开 → 已改为：悬停仅重新显示（关闭后），不解除最小化，
  恢复大小仅靠 — 按钮；点 × 后 userClosed；内容：蓝量/容量/充能/施放数 +
  法术槽网格（8/行，windowHeight 按槽位数动态计算，用户手动缩放优先）。
- 小包悬浮窗：已有 UI 时右键容器槽位小包 → 悬浮窗；手持右键 → 容器 UI。
- 窗口缩放：无最大化；拖动左/右/下边+下角（4px 判定区）缩放，
  缩放后背景面板自动拉伸（stretchBackgroundPanels）。
- 槽位拖拽：拾起渲染层隐藏、拖拽跟手、释放产生交换意图（原版瞬时交换，
  无飞行动画）；槽位 stack 永远以服务端同步为准。
- 法术槽网格（SpellSlotGrid）：可变槽位 UiElement，网格对象固定，setCount 只
  增删内部槽位，refresh 只更新 slot.stack；构建时替换 spell-grid 占位符后
  不再动 window.content。
- 投放决策（ContainerWindowBase.tryRemoveToContainer）三级：跨浮窗 >
  容器槽位（坐标定位）> 背包回退；创造模式 silent 删除；拖动内容 =
  ctrl.carriedStack() 权威快照。
- 抽象基类 TrackedContainerWindow：按 ID 定位（手持/副手/背包）→ 网格更新
  → 丢失处理，法杖窗/小包窗共用。
