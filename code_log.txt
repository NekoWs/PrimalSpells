一、项目模块总览
------------------------------------------------------------
- item/        WandItem(法杖)、SpellPouchItem(法术小包)、ModItems(注册)、
               SpellPouchInventory/Menu(容器)、ModMenus(MenuType)

               effect/ 与 projectile/ 下大量法术

    - UiScreen/UiBuilder/UiElement(UiWindow/UiButton/UiLabel/UiImage/UiSlot)
    - html/HtmlUiParser（HTML→UI 转换器）、HtmlUiLoader

    - pouch/SpellPouchWindow + PouchWindowManager（小包悬浮窗）
    - slot/SlotDragController + SlotSwapAnimation（槽位拖拽/交换动画）
    - common/SpellSlotGrid + ContainerWindowBase（通用容器浮窗基类）
- block/       WandEditingTableBlock（法杖编辑台）
- network/     SyncWandStatsPayload、EditWandPayload、EditPouchPayload
- client/      PrimalSpellsClient、ClientTooltipHandler、WandHudRenderer、
               SpellPouchScreen、PouchTooltip
- mixin/       AbstractContainerScreenMixin（getHoveredSlot 屏蔽、tooltip）

二、关键修复历史（按时间序）
------------------------------------------------------------
1. 编译错误：缺失 client/entity 渲染类 → 按 26.2 新渲染管线
   （EntityRenderState + SubmitNodeCollector.submitModel）补齐 6 个文件。
2. DroneEntity tickCount 隐藏父字段、canBeAffected 废弃 → 重命名/移除。
3. 无人机碰撞箱 0.6x1.6 → 0.35x0.35（对齐模型）。
4. "Block id not set"：BLOCKS.register 的 lambda 参数是 Identifier，
   必须 `.setId(ResourceKey.create(Registries.BLOCK, key))` + `.noLootTable()`。
5. 编辑台"网络协议错误"：MenuType+AbstractContainerMenu+Screen 方案导致
   ClientboundOpenScreenPacket 问题（RegisterMenuScreensEvent 时机存疑）→
   改为纯客户端 Screen（Minecraft.getInstance().gui.setScreen）绕开。
   注：小包容器 UI 恢复用菜单系统（ModMenus + RegisterMenuScreensEvent），
   目前工作正常，说明当初编辑台协议错误另有隐情（未深究）。
6. @JvmStatic + NeoForge.EVENT_BUS.register(实例) 冲突崩溃 → 去掉 @JvmStatic。
7. ModuleClassLoader.getResourceAsStream 在 Windows dev 崩溃
   （WindowsPathParser 异常）→ 改用 ResourceManager / dev 文件系统读取。
8. F3+T 热重载无效：dev 环境资源实际从 build/resources/main 加载，
   改 src 不生效 → HtmlUiLoader 优先读源码目录文件（Path 向上两级找项目根）。
9. 悬浮窗被 Screen 遮挡：HUD(RenderGuiLayerEvent.Post) 在 Screen 之前渲染 →
   改用 ScreenEvent.Render.Post（Screen 渲染之后）。
10. 编辑台背景模糊 → UiScreen.isInGameUi()=true。
11. 悬浮窗"闪烁/几乎隐藏"：曾用 gameTime 去重（20tps）导致高帧率下每 tick
    只画一次 → 删除去重；改为 refresh 内容缓存（仅变化时更新）。
12. 数据不同步（多次）：
    - WandInfoWindow：缓存 ItemStack 引用，容器同步后引用失效 →
      改缓存 wandId，每次 refresh 用 findWandById 从 containerMenu 重新查找。
    - SpellPouchWindow：同样改为 locatePouch() 按 pouchSlotIndex 每帧重取。
    - 结论原则：浮窗数据永远不要缓存物品引用，每次刷新从容器解析。
13. 复制物品 bug：ADD 时客户端清了光标但服务端未清 → 服务端 clearCarriedSpell。
14. REMOVE 物品丢失：目标槽是小包时被覆盖、addItem 失败时物品消失 →
    小包保护 + giveOrCarry（背包满回退光标）。
15. 卸载永远回背包：目标槽判定依赖 hoveredSlot（渲染期更新，拖放瞬间陈旧）→
    用坐标精确定位（Slot.x/y 是相对菜单坐标，需 + getLeftPos()/getTopPos()）。
16. 【记录错误，已更正】当时以为 getLeftPos 运行时不存在而改用 getGuiLeft。
    实测 26.2 源码：getLeftPos()/getTopPos() 是 NeoForge 添加的官方 getter，
    getGuiLeft()/getGuiTop() 是 Mojang 旧 API（deprecated，内部委托 getLeftPos）。
    两者都能用；"放错格"的真正修复是第 19/20 项的拖放重构与 pouchId。
    【教训】~/.gradle/caches/neoformruntime/ 下存在其他项目（1.21.1）的残留缓存，
    javap 前务必确认 jar 来源（26.2 正确产物在 build/neoForm/neoFormJoined26.2-1/）。
17. 跨浮窗拖动缺失：法杖窗拖到小包窗被当"卸载" → ContainerWindowBase 注册表

24. 【最新·教训】HTML 根 div 的 title 只能作为窗口标题，禁止再生成正文区面板标题：
    - 根因：parseWindowed 把 div.title 作为窗口顶栏标题（HtmlUi.title），
      但 convert 又把同一属性传给 UiWindow（正文区顶部面板标题）→ 双标题。
      第一次修复：convert 增加 windowRoot 参数，根 div 不再生成面板标题（游戏内已修复）。
      第二次复发：uichecker 预览端 buildNode 对所有 div 渲染 title 子元素
      （.mc-panel-title），根 div 再次出现双标题。
    - 【规则】HTML title 属性用途：
      * 窗口根 div 的 title → 仅顶栏标题（FloatingWindow/UiScreen 标题栏）
      * 嵌套 div 的 title → 面板标题（允许）
      * uichecker 与游戏转换器必须同步遵守，修游戏侧必查预览端、反之亦然。

三、26.2 易踩坑技术点（务必记住）
-----------------------------------------------------------
- 26.2 API 勘误（与 1.21.x 的差异）：
  * ClickType → ContainerInput（PICKUP/QUICK_MOVE/SWAP/CLONE/THROW/PICKUP_ALL）
  * Minecraft.getTimer() → getDeltaTracker()（返回 DeltaTracker）
  * net.minecraft.Util → net.minecraft.util.Util
  * Screen.hasShiftDown() 静态方法已移除 → Minecraft.getInstance().hasShiftDown()
  * AbstractContainerScreen：getLeftPos()/getTopPos()（NeoForge getter）、
    getHoveredSlot()（NeoForge getter）；getGuiLeft()/getGuiTop()/getSlotUnderMouse()
    已 deprecated（委托新方法）
- javap 验证类时注意 ~/.gradle/caches/neoformruntime/ 可能混有其他项目版本
  （如 1.21.1）的残留 jar，26.2 正确产物在 build/neoForm/neoFormJoined26.2-1/。
- 物品模型：assets/<ns>/items/<name>.json（ItemModelDefinition）引用
  models/item/<name>.json。缺 items/*.json 则物品贴图不生效。
- GUI atlas 只扫描 textures/gui/sprites/；容器背景是直接纹理
  textures/gui/container/*.png + graphics.blit(RenderPipelines.GUI_TEXTURED,
  id, x, y, 0f, 0f, imageWidth, imageHeight, 256, 256)（照抄 CraftingScreen）。
- Slot.x/y 是相对菜单坐标，屏幕坐标 = getLeftPos()+slot.x。
- ScreenEvent.Render.Post 在 Screen 渲染后触发（浮窗最上层）；
  RenderGuiLayerEvent.Post(HUD) 在 Screen 之前。
- Screen.isInGameUi() 控制背景模糊/暗化与 HUD 显示。
- NeoForge.EVENT_BUS.register(对象) 的 @SubscribeEvent 方法不能 @JvmStatic。
- 客户端发包用 ClientPacketDistributor.sendToServer（不是 PacketDistributor）。
- 输入体系：mouseClicked(MouseButtonEvent, boolean)、keyPressed(KeyEvent)；
  ScreenEvent.MouseButtonPressed/Dragged/Released.Pre 可拦截并 event.isCanceled。
- 构建/改资源前先结束游戏进程（Windows 文件锁）。
- dev 改 src 资源后需 processResources 或重启（build/resources/main 才生效）；
  HTML 例外（dev 直接读源码目录）。

四、UI/交互架构现状
------------------------------------------------------------
- 法杖信息浮窗（FloatingWindowManager）：
  * 打开游戏内 UI（isInGameUi）时显示最小化窄顶栏（右侧 56px）；
  * 悬停物品栏中的法杖（hoveredSlot.item is WandItem）→ 展开；
  * 移出不自动收起；点 × 后 userClosed，再悬停法杖重新显示；
  * 内容：蓝量/容量(含 size)/充能/施放数 + 动态法术槽网格（8/行）。
- 小包悬浮窗（PouchWindowManager）：
  * 已有 UI 时右键容器槽位小包 → 悬浮窗（拦截原版拾取）；
  * 手持右键小包 → 服务端容器 UI（PouchEventHandler.openMenu + extraData）。
  * 渲染双通道：有 Screen 用 ScreenEvent.Render.Post，无 Screen 用 HUD 层。
- 槽位拖拽（SlotDragController，数据权威化）：
  * 拾起（渲染层隐藏 picked）、拖拽跟手、交换动画（纯视觉缓入缓出）、
    槽位 stack 永远以服务端同步为准，拖动过程不修改数据。
- 投放决策（ContainerWindowBase.tryRemoveToContainer）三级：
  跨浮窗(acceptExternalSpell) > 容器槽位(坐标定位放置/交换) > 背包回退。
  拖动内容 = ctrl.carriedStack()（拾起瞬间权威快照，源槽数据未被破坏）。
