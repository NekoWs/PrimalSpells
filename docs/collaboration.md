# 协作方式：委派开发 + 主 agent 验收

新需求默认由主 agent 把需求翻译成**自包含 prompt**，交给子代理（`local/qwen3.8-flash-next`）开发；**主 agent 不亲手写代码**，只负责核对功能是否真的完成。用户当次指令优先于本文件全部条款。

## 1 一轮需求的完整流程

| 步 | 谁 | 做什么 | 完成判据 |
|---|---|---|---|
| 1 定清需求 | 主 | 需求有歧义或缺口细节，先问用户 | 能写出自包含 prompt：输入 / 输出 / 验收点俱全 |
| 2 定稿计划（仅多步需求） | 主 | `commit_star` → `edit_plan` L1+L2 → `lock_stage`，锁定后的计划即 spec | 计划树锁定，每个小类带可核对的验收标准 |
| 3 委派 | 主 → 子 | `subagent(provider: local, model: qwen3.8-flash-next)`，prompt 按 §3 组装 | 子代理返回交付说明 + 证据（改动清单、命令原始输出） |
| 4 验收 | 主 | 逐条核对需求；`./gradlew build`；读 diff 对 `conventions.md`；视觉/手感类核对 §4 的录制证据 | **每条需求都有证据**（文件:行 / 命令输出 / 判定行） |
| 5 打回或提交 | 主 → 子 | 不通过 → 问题清单 `send_message` 回**同一个**子代理续跑；通过 → 通知它提交（只暂存本次相关文件） | 构建绿、台账已回填、工作树只剩用户原有改动 |

**多步需求** = 要改 ≥2 个互不相干的区域，或有 ≥2 个可独立验收的交付物。

## 2 上限与等待：慢不等于失败

**上限 2 轮**：首轮交付 + 1 次带证据的打回。第 2 轮仍不过就**停下通知用户**，报告里给三样东西：两轮打回史、当前证据、我的建议（换方案 / 换模型 / 我上手）。不自行加轮次，不换模型硬试。「轮」按子代理的**交付次数**计，不按挂钟时间计。

**慢不等于失败**：本地 qwen 约 30 tok/s，一次写码交付几十分钟是常态。委派后进入等待态，判据只有两个——子代理**自己报完成**，或**自己报阻塞 / 做不了**。等待时长本身永远不构成失败、超时或接管的理由；尤其不允许「还没写好 → 估计不行 → 我自己写」。配套三条硬规矩：

1. **一律后台跑**：`subagent(...)` 保持默认 `run_in_background: true`。前台阻塞等待的时长上限会逼出误判，也会把本轮对话挂住。
2. **派完不停在那儿看**：转去做其它独立的事，或直接结束本轮；子代理落定后运行时会给我通知，不靠轮询猜进度。
3. **只在两种情况下干预**：它的报告显示确实空转（同一处报错、同一处解释连续两轮不动），或它主动来问。此外不打断、不催促、不因为「安静」而判定它死了。

## 3 委派 prompt 必须包含

- **任务**：交付什么，以及明确不做什么（非目标）。
- **指路**：`AGENTS.md` 的路由表 + 命中的 `docs/` 篇目（改法术内容 → `spell-development.md`；动核心机制 → `architecture.md` §8；写代码前 → `conventions.md`）。
- **硬性要求**：把 `AGENTS.md` 的硬性要求 1–7 原样贴进 prompt，子代理不必自己找。
- **本次额外约束**：**先不要 `git commit`**（提交时机在验收通过后）。
- **交付定义**：改动清单 + 命令原始输出 + 视觉/手感类的录制证据。
- **报错口径**：报 `文件:行` + 报错原文，不要只描述现象。
- **节奏**：本地推理约 30 tok/s，慢没关系；但**范围不打折**——不留 TODO、不缩水未做完的项，做不完就如实列出哪几项没做。

`reasoning_effort` 默认 `medium`；核心机制类（法术结算、effect 顺序、牌堆、持久化）可提到 `xhigh`。

## 4 验收证据

| 需求类型 | 必须看到的证据 |
|---|---|
| 任何需求 | `./gradlew build` 的原始输出（含 BUILD SUCCESSFUL 那几行） |
| 逻辑 / 数值 | 改动 diff + 逐条需求对应的 `文件:行` |
| 视觉 / 手感 | `build/capture/out/report.txt` 的 PASS/FAIL 判定 + `index.html` 或 `<scene>/contact.png` / `<scene>.gif`；**代码审查通过不算过**，以录制判定为准 |
| 收尾 | 台账已按 `issues/README.md` 规则回填（open 删条、结论进 resolved） |

## 5 主 agent 直做、不委派的范围

单文件、≤10 行、且不触碰核心机制（法术结算 / effect 顺序 / 牌堆 / 持久化）——纯文档、语言键、贴图路径这类。超出任意一条即委派。

## 6 主 agent 的改动权限

验收中发现小瑕疵可直接修：编译错、格式、命名、漏 import，累计 ≤5 行，并在验收报告里列出改了哪几行。超出一律打回子代理——**实现代码由子代理写**。

## 7 不进流程的情形

纯问答、只读调查（找代码、看构建状态）直接做。用户当次说「你直接改」时照做，不受本文件约束。
