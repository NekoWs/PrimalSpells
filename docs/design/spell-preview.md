# 编杖与法术链分色

使用原版容器内物品交互编杖，法术链直接以槽位底色区分。没有悬浮编辑窗。

## 使用

在背包或箱子里悬停法杖，用滚轮选择槽位。拿起一张散卡后右键法杖装入/替换；空光标右键取出所选槽的卡。原有Ctrl＋左键拖动交换物品、Alt查看数值保持可用，不弹出编辑窗口。

法杖tooltip的槽位背景直接按法术链分色，同一作用域同色，触发/定时/失效荷载使用单独颜色，空槽保留原版背景。白色细边标记滚轮选中的槽，不覆盖链底色。首次悬停等待服务端结果时只显示原版底色，不猜测作用域。

V保留为独立只读预览：在容器中悬停法杖按V，或在世界中手持主手/副手法杖按V。预览仅显示分色槽位、下一次施法费用/双冷却与失败原因，不再展开冗长的文本抽牌树。Esc返回原菜单；按键可在控制设置中改绑。

## 权威语义

Wand.preview委托WandPreviewBuilder，在独立的牌堆、卡牌和法力副本上调用WandDeck与CastTransaction，不执行spell/onActive/世界钩子，不改变原杖MP、冷却或牌堆。下一次施法的结算预览仍保留展开树数据，界面展示简化为槽位背景。

整副配置的分色同样复用WandDeck.draw：从配置首槽开始，在隔离副本上依次观察每条链，禁止回洗、不付费，不随当前MP或已施放到哪一张而改变颜色。抽牌器的可选trace只观察原卡所属作用域，不改变实际抽牌逻辑。复制单卡、全量施放和追加荷载均走原语义；按卡牌对象身份关联槽位，不按法术ID猜测，重复卡牌也能正确区分。

客户端WandPreviewCache只保留最近悬停的一根杖，每10t最多一次请求，服务端限流5t；换杖/装卸时清掉旧颜色，仅接受法术槽列表与当前配置完全一致的响应，登出清空。不在客户端另写解析器。4096行/槽位为网络上限；正常法杖最多18槽。

## 编辑与网络

生存装卸走原版PICKUP协议与WandItem.overrideOtherStackedOnMe；滚轮SelectSpellSlotPayload在当前可拾取菜单槽和玩家背包查找真实物品，并校验槽位范围，因此箱子里的法杖也能选槽。

创造物品栏的光标按原版由客户端选取，因此CreativeWandEditHandler仅把右键法杖装卸交给已有EditWandPayload，不显示窗口，不接管其他物品/左键/Shift操作。服务端只接受创造玩家、真实菜单槽/wandId、注册散卡与合法数量，拒绝任意物品组件；完整菜单同步回交光标。生存玩家不能走这个专用包。

WandPreviewPayload由ModNetworking注册，经ClientPayloadSink和RegisterClientPayloadHandlersEvent接线，服务端校验集中在WandRequestHandler。当前协议1.8.0，包含整副槽位归属；客户端/服务端同步升级，不修改原法术id、wandId和存档键。tooltip使用原版bundle槽背景与法术物品模型，资源包可覆盖其引用资源。

## 验证

foundations覆盖真实V键绑定/容器V事件、真实菜单右键取出/装入/替换、原滚轮同步、重复卡与独立荷载分色、零MP完整分组及预览前后编辑。spell_chain覆盖作用域和收费语义；复现命令见 [构建与运行](../build-and-run.md)。
