# 引用、刷新与生命代价

数值见 [战斗规则](combat-pricing.md#3-资源与节奏)。卡牌类型：缩短存在时间、血魔法属于修正；希腊引用、遁入虚空、刷新法杖及一分为多属于其他。显示名按当前约定使用Alpha、Gama、Tau、Omiga、Miu、Phi、Sigma、Zeta；持久化ID使用标准小写拼写，不随显示名改动。

## 1. 引用作用域

引用读取本杖完整装载配置（固定卡在前，空槽跳过），不局限于剩余抽牌堆。引用副本进入当前链，仍遵循本链修正无顺序、触发荷载独立的规则。引用本身不抽走原卡；副本中的触发、追加和抽牌控制仍正常抽牌。已选副本先由独立游标读取，缺少触发荷载时继续从当前实际牌堆抽取。

| ID | 行为 |
|---|---|
| alpha | 复制本杖首张非空卡 |
| gamma | 复制本杖末张非空卡 |
| tau | 复制当前游标后方最多两张卡；复制单卡，不复制整条法术链 |
| omega | 复制本杖除当前这张实体卡与全部刷新卡外的卡；其它引用卡仍正常展开 |
| mu | 复制本杖全部Modifier，随后继续抽取一个法术；多重施放修正仍可增加其抽牌预算 |
| phi | 复制模板初速非零的全部Projectile |
| sigma | 复制模板初速为零的全部Projectile；不按速度修正后的运动状态改变分类 |
| zeta | 随机选择随身另一根非空法杖，再随机复制其中一张卡；玩家查背包与副手，生物查主副手 |

Miu/Phi/Sigma仅免除被选复制卡本身的MP、delay、recharge，以及链锯的delay归零；其它效果保留。复制品另行抽到的实际荷载正常付费。生命代价不属于以上三种免除项目。其余引用复制卡按正常费用结算，不能默认享受Noita式免费施法。

引用控制卡未付费时，其展开内容不付费、不释放。复制品保留已准备的费用状态和独立荷载树，二次复制不会恢复已免除的费用。Zeta的资源由施法杖支付，不改写来源杖的牌堆、MP或冷却。

直接或间接再次引用当前正在展开的同一张控制卡时跳过该引用；相同ID的不同实体卡仍可组合。空引用消耗当前抽牌预算，不误施放下一张卡；只有获得普通修正时才继续抽其需要的投射物，Miu明确继续抽牌。单次展开最多4096个准备节点、64层递归，超过时停止新增节点并保留Expansion limit原因；不产生无限递归或无界复制树。

Zeta随机流由Wand.referenceSeed驱动；预览不推进，真实施法结束推进并保存reference_seed。预览与实际施法共享解析器/结算器。配置变化后预览需重新获取。

## 2. 刷新

刷新是抽牌控制，不生成弹体。单张成功付费的刷新使事务立即重新装填完整牌堆，并清除本次充能等待；仍保留施放延迟。正常抽牌只消费该卡的一个预算，多重施放可在同次事务接受多张刷新。

同次事务接受两张及以上（包括引用/一分为多的复制品与已付费荷载）时，重新装填后按普通基础充能加卡牌recharge结算，最终至少零刻。未付费刷新不强制重装填。刷新与当前手牌、旧弃牌合并后只保留完整配置的一份实体牌，不将副本写回真实牌堆或存档。

## 3. 寿命与生命代价

延寿/减寿使用LifetimeAdjustment：先汇总全部加值，再钳制到至少一刻，在视觉激活前完成。不会先钳制某张卡造成顺序差异，也不会把负寿命当成无限寿命。

血魔法是事务生命付费：每张成功接受的卡付一次，根链与荷载统一汇总，不随弹体数量、穿刺接触或后续荷载释放次数重扣。只读预览不修改HP。复制的血魔法是独立卡，仍需各付一次生命代价。

CURSE有独立伤害类型与原版风格死亡文本；付款走hurtServer和战斗记录，绕过护甲、抗性、附魔、盾、无敌帧与吸收生命，可能致死。死亡后不再发射本次付费弹体。保留已有吸收生命，不把它拿来支付HP代价。

## 4. 无界之界

遁入虚空为主动OtherSpell，直接影响施法者，也可以作为已付费荷载执行。状态采用原版MobEffect计时/保存，可见性布尔值通过NeoForge同步附件同步给所有追踪观察者（原版非玩家效果实例只同步给乘客），不覆盖原有隐身、无敌标志或游戏模式。期间不被本模组接触、索敌、区域伤害或区域迟缓/吸引影响，也不被原版箭的可命中契约或原版TargetingConditions选中；进入时清除附近Mob已有攻击目标和Brain攻击记忆。

期间拦截对外伤害、近战、物品使用、方块交互和后续施法；装备、手部、姓名、阴影、轮廓与实体本体一并隐藏。被动卡与持杖阵列走现有退场，不创建额外特效。持续时间结束恢复原有能力；登出/玩家换维清除此状态。不会传送、更改碰撞体积或穿墙。

## 5. 实体卡使用次数

`Magic.maxUses`为0时不限次，正数声明每张实体卡的上限。遁入虚空每张25次；两张同名卡各自计数，不以法术ID、玩家或法杖汇总。次数耗尽保留实体卡，直接抽到时不接受该卡、不计其MP与双冷却，仍可由引用或一分为多复制施放。复制仍按原有规则支付MP与时间，免次数与免费复制是两个独立规则。

正常抽牌从工厂创建运行实例，同时绑定原实体卡；工厂`clone()`本身不是玩法复制。付款事务预留本次可用次数，只有通过施法门槛/事件、付费且生命付款后仍存活时才提交。装备预热、冷却、虚空禁用、事件取消、付款失败和只读预览不扣次数。荷载与MP一样在原施法事务预付一次，未触发也不返还；命中重复释放、碰撞子步和延迟到期不再扣次数。玩法复制的整棵准备树（包括荷载）不扣原卡次数。

剩余次数随实体卡装卸、交换、存入小包和存档保留；回洗、刷新法杖与`load()`不会补满。散卡用`spell_uses`物品组件，小包用`pouch_spell_uses`逐槽保存，法杖权威NBT用`spell_uses`/`innate_uses`逐槽保存。三牌堆新增`*_slots`索引恢复实体身份，防止同名卡在读档后交换次数；旧ID列表保留供兼容，旧卡缺少次数数据时按满次数读取，明确的0不重置。

单卡与选中槽tooltip显示剩余/上限，耗尽说明仍可复制；法杖、小包网格及V预览显示各槽剩余次数，耗尽为红色0。`wand_spell_uses`仅为服务端同步展示副本，不能当作法杖权威来源。

## 6. 实机回归

new_spells中ReferenceSpellChecks检查引用选择、复制费用与荷载、空引用/循环/展开上限、刷新次数、预览一致与只读、NBT恢复、寿命、真实HP付款及Zeta来源杖只读。foundations中的LimitedUseChecks覆盖逐卡扣次、25次耗尽、耗尽卡复制、荷载预付、装卸/小包与NBT，并验证真实网络中的次数展示。VoidSpellChecks持续驱动状态并读取原版可命中/索敌/受伤、交互事件与客户端原生render state；同时保留锯片/治疗/火把和旧抽牌回归。运行命令与证据入口见 [构建指南](../build-and-run.md)。

次数与链路机制、界面同步/显示的验证结果见[构建指南](../build-and-run.md#9-实机录制流水线)；new_spells混合退场判据未通过的部分单列在[未解决问题](../issues/open.md)。长时多人延迟、第三方自定义渲染器的兼容体验尚未覆盖，不将单客户端追踪同步视作完整联机压力验证。
